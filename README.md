# SPSMC Build No Ores

Paper の `build` ワールドだけを対象に、自然生成された鉱石を石・深層岩へ置き換える小さなプラグインです。

通常地形のワールド生成を使うため、山・洞窟・バイオームなどは残ります。`resource`、`lobby`、その他のワールドは対象外です。

## 動作

- `build` ワールドの `WorldInitEvent` で `BlockPopulator` を登録します。
- 新しく生成されるチャンクの中央16×16ブロックを走査します。
- 自然生成された鉱石ブロックを次のように置き換えます。
  - 通常の鉱石 → `stone`
  - 深層岩の鉱石 → `deepslate`
- 既存チャンクの置換は自動実行せず、必要なときに手動スキャンまたは停止中のオフライン補助を実行します。
- スキャン完了フラグを設定ファイルへ保存し、明示的な再実行以外では再処理しません。
- スキャン開始時に、既存の生成済みチャンク座標を`existing-build-chunks.txt`へ保存します。
- スキャン開始・完了時には、保存対象のチャンク数と外接範囲も表示します。
- 新規チャンクの生成時処理では、後から設置された鉱石は対象にしません。

既存チャンクのスキャンは、リージョンファイルに記録されたチャンクのうち、生成完了済みと確認できるチャンクだけを対象にし、新しいチャンクを生成しません。生成途中のチャンクは対象から除外し、対象チャンクは生成せずに読み込み、読み込めない場合は再試行します。各チャンクの置換直後にも鉱石残存数を確認し、残存があれば失敗扱いにします。全対象を処理・検証できた場合だけ完了フラグを設定し、未処理チャンクが残った場合は完了扱いにせず再実行できます。座標ファイルには`chunk_x,chunk_z`を1行ずつ記録し、建築ワールド自体のチャンクを削除・再生成しません。実行中にサーバーを停止した場合も完了フラグを設定しません。完了後の再実行はできません。生成途中チャンクのNBTを変更する必要がある場合は、サーバー停止中にインフラ側のオフライン補助を使用します。

鉱石ブロックだけでは自然生成かプレイヤー設置かを判別できないため、既存スキャンでは両方が置換対象になります。実行前にバックアップを取得し、建築ワールドを利用するプレイヤーがいない時間帯に実行してください。

## ビルド

```sh
mvn clean package
```

生成物:

```text
target/spsmc-build-no-ores-0.2.0.jar
```

## 導入

生成したJARをPaperサーバーの `plugins/` に配置して再起動します。

既存の生成完了チャンクを手動でスキャンする場合:

```text
/buildnores scan
```

完了フラグがすでに`true`でも、明示的に既存チャンクを再処理する場合は次を使います。既存スキャンはプレイヤーが設置した鉱石も置換対象になるため、実行前に確認してください。

```text
/buildnores rescan
```

既存チャンクのスキャンは起動時には実行されません。完了すると`plugins/SPSMCBuildNoOres/config.yml`の`migration.existing-build-scan-completed`が`true`になります。以後も新規チャンクは生成時に継続して鉱石を置換します。

このリポジトリの正本へ組み込む場合は、JARの配置方法と `plugin-urls.txt` またはDockerのビルド方法を別途決めてから反映します。
