# SPSMC Build No Ores

Paper の `build` ワールドだけを対象に、自然生成された鉱石を石・深層岩へ置き換える小さなプラグインです。

通常地形のワールド生成を使うため、山・洞窟・バイオームなどは残ります。`resource`、`lobby`、その他のワールドは対象外です。

## 動作

- `build` ワールドの `WorldInitEvent` で `BlockPopulator` を登録します。
- 新しく生成されるチャンクの中央16×16ブロックを走査します。
- 自然生成された鉱石ブロックを次のように置き換えます。
  - 通常の鉱石 → `stone`
  - 深層岩の鉱石 → `deepslate`
- `build`ワールド読み込み後、既存の生成済みチャンクを自動で一度だけスキャンします。
- スキャン完了フラグを設定ファイルへ保存し、完了後の再実行を拒否します。
- スキャン開始時に、既存の生成済みチャンク座標を`existing-build-chunks.txt`へ保存します。
- スキャン開始・完了時には、保存対象のチャンク数と外接範囲も表示します。
- 新規チャンクの生成時処理では、後から設置された鉱石は対象にしません。

既存チャンクのスキャンは、リージョンファイルに記録された座標だけを対象にします。生成途中の既存チャンクは通常のワールド生成で完了状態まで進め、生成完了後に読み込みます。リージョンに記録されていない新しい座標は生成せず、読み込めない場合は再試行します。各チャンクの置換直後にも鉱石残存数を確認し、残存があれば失敗扱いにします。全対象を処理・検証できた場合だけ完了フラグを設定し、未処理チャンクが残った場合は完了扱いにせず再実行できます。座標ファイルには`chunk_x,chunk_z`を1行ずつ記録し、既存チャンクの削除は行いません。実行中にサーバーを停止した場合も完了フラグを設定しません。完了後の再実行はできません。

鉱石ブロックだけでは自然生成かプレイヤー設置かを判別できないため、既存スキャンでは両方が置換対象になります。実行前にバックアップを取得し、建築ワールドを利用するプレイヤーがいない時間帯に実行してください。

## ビルド

```sh
mvn clean package
```

生成物:

```text
target/spsmc-build-no-ores-0.2.0.jar
```

## 導入

生成したJARをPaperサーバーの `plugins/` に配置して再起動します。

自動スキャンに失敗または未完了になった場合の手動再試行:

```text
/buildnores scan
```

完了フラグがすでに`true`でも、明示的に既存チャンクを再処理する場合は次を使います。既存スキャンはプレイヤーが設置した鉱石も置換対象になるため、実行前に確認してください。

```text
/buildnores rescan
```

通常は`build`ワールドの読み込み後に自動実行されます。完了すると`plugins/SPSMCBuildNoOres/config.yml`の`migration.existing-build-scan-completed`が`true`になります。以後の新規チャンクは生成時に継続して鉱石を置換します。

このリポジトリの正本へ組み込む場合は、JARの配置方法と `plugin-urls.txt` またはDockerのビルド方法を別途決めてから反映します。
